# amoCRM → Sendsay: Inbound «Не удалось связаться»

Каждый час берёт сделки воронки **Inbound** (id 8454514) на этапе «Закрыто и не реализовано», у которых
поле **«Причина отказа.»** (id 701893) = **«Не удалось связаться»**, и добавляет основной контакт сделки
в список Sendsay **Inbound (не удалось связаться)** — `pl42130`.

**Берутся только контакты с включённым «Согласием на рекламные рассылки»** (поле контакта, id 704923).

Передаются поля (в существующие анкеты Sendsay):

| amoCRM | Sendsay |
| --- | --- |
| Email контакта | `member.email` |
| Имя | `base.firstName` |
| Фамилия | `base.lastName` |
| Компания | `custom.kompaniya` |
| ID сделки | `custom.id_sdelki` |
Без согласия или без email контакт пропускается. Дубли по email схлопываются.

## Файлы
- `sync_noreach.py` — сам скрипт
- `.github/workflows/sync-noreach.yml` — расписание и ручной запуск (положить по этому пути)

## Настройка

**1. Секреты репозитория** (Settings → Secrets and variables → Actions):
- `AMO_TOKEN` — долгосрочный токен amoCRM (можно тот же «Универсальный токен SS», нужны права на чтение сделок, контактов, компаний)
- `SENDSAY_LOGIN` — общий логин аккаунта Sendsay
- `SENDSAY_APIKEY` — API-ключ Sendsay (Настройки системы → API-ключи)

**2. Поля в Sendsay** уже есть (см. таблицу выше), создавать ничего не нужно. Другие поля — через переменную `SENDSAY_FIELDS`.

**3. Проверка полей.** Actions → workflow → Run workflow → `describe`. Скрипт покажет название поля согласия
(должно быть «Согласие на рекламные рассылки») и поля всех анкет Sendsay (сверить, что `kompaniya` и `id_sdelki` на месте). Если ID согласия другой — задайте
`AMO_CONSENT_FIELD_ID` в `env` workflow.

**4. Тест на одном адресе.** Run workflow → `test-email` → свой email. Проверьте в Sendsay, что адрес появился
в списке `pl42130` и поля анкеты заполнены. Если контакт попал в базу, но не в список — значит у вашего аккаунта
другое имя параметра списка в `member.import`; поправьте строку `auto_group` в `push_to_sendsay`
(уточнить можно в API-консоли Sendsay или у поддержки).

**5. Пробный прогон бэкфилла.** `dry-run` (можно с `since_days: 180`) — покажет, сколько сделок и контактов
найдёт, ничего не отправляя.

**6. Бэкфилл.** `full` (с `since_days: 180` или пустым — вся история).

**7. Дальше всё само:** раз в час — сделки, изменённые за последние 3 часа.

## Как ведёт себя
- Повторы безопасны: контакт обновляется (`must_merge`), в список повторно не дублируется.
- Если причину проставили не сразу, а позже — сделка всё равно подхватится (меняется `updated_at`).
- Отписавшихся Sendsay обратно не подпишет.
- Только этап 143: `ONLY_LOST=0` — брать сделки с этой причиной на любом этапе.
  Все контакты сделки, а не только основной: `MAIN_CONTACT_ONLY=0`.
